## 核心症状与 30 秒诊断决策

当遇到 **“Clash 节点测速全绿，但网页就是打不开”** 时，请按照以下故障树进行快速定位：

```mermaid
graph TD
    Start[问题: 节点测速正常但打不开网页] --> Step1{国内网站 (baidu.com) 能打开吗?}
    Step1 -->|不能| Fix1[本地网络断开 / 系统代理端口死锁 ➔ 重启网络与 Clash]
    Step1 -->|能| Step2{切换到其他国家节点能否打开?}
    Step2 -->|能| Fix2[原节点落地服务器维护 / 被目标站封锁 ➔ 更换节点]
    Step2 -->|不能| Step3{系统时间与北京时间误差 > 60秒吗?}
    Step3 -->|是| Fix3[时钟偏差导致 TLS 握手失败 ➔ 立即同步时间]
    Step3 -->|否| Fix4[DNS 污染或 TUN 虚拟网卡驱动异常 ➔ 重装服务模式]
```

## 一、导致“有节点却无网速”的 5 大根本原因

### 1. 本地系统时钟不同步（最常见）
现代加密协议（VLESS、Shadowsocks 2022、VMess）对时间戳校验极其严格。如果电脑系统时间快或慢了 60 秒以上，服务端将直接拒绝解密 TLS 请求，表现为“测速正常，但任何网页都无法握手”。

### 2. 系统代理端口死锁与注册表残留
非正常关机、软件闪退可能导致 Windows 代理注册表依然指向旧端口（如 `127.0.0.1:7890`），而新启动的 Clash 使用了其他端口，导致流量被抛弃进黑洞。

### 3. 浏览器插件冲突（如 SwitchyOmega）
如果在 Chrome 安装了代理插件且设置为非“系统代理”模式，浏览器的请求将被插件强制转发，完全绕过 Clash。

### 4. TUN 虚拟网卡驱动服务未安装
开启了 TUN 模式但没有安装底层 Service Mode 服务，导致虚拟网卡没有实际接管流量。

### 5. 节点仅 TCP 连通但落地机器脱网
机场上游节点服务器可能遭遇了落地机房拔线或 DNS 故障，仅前端接入机响应 Ping，后端无法转发数据。

## 二、4 步逐步排查与修复流程

### 第一步：强制同步 Windows / Mac 系统时钟
- **Windows**：按 `Win + I` 打开「设置」➔「时间和语言」➔「日期和时间」➔ 点击 **「立即同步」**。
- **macOS**：打开「系统设置」➔「通用」➔「日期与时间」➔ 确保开启「自动设置时间」。

### 第二步：重置系统代理与清理浏览器插件
1. 在 Clash Verge 设置中关闭「系统代理」。
2. 按 `Win + R` 输入 `inetcpl.cpl` 打开 Internet 选项 ➔ 点击「连接」标签页 ➔ 点击底部的「局域网设置」。
3. 取消勾选「为 LAN 使用代理服务器」，点击确定。
4. 重新回到 Clash Verge 开启「系统代理」。

### 第三步：切换模式为「规则 (Rule)」并切换策略组
1. 打开 Clash Verge「代理」页面。
2. 确认顶部选中的是 **「规则 (Rule)」** 模式。
3. 在 `PROXY` 组中，选择一个新加坡或日本的备用专线节点测试。

### 第四步：重新安装 Service 模式与开启内置 DNS
1. 在 Clash Verge 设置中找到「服务模式」，点击安装并授权管理员权限。
2. 开启内置 DNS，设置主 DNS 为 `223.5.5.5`，Fake-IP 模式开启。
3. 重启 Clash Verge 客户端。

---

## 三、排错成功验证

完成上述步骤后，打开命令行工具（CMD / Terminal）运行：
```bash
curl -I https://www.google.com
```
若返回 `HTTP/2 200` 或 `HTTP/1.1 200 OK`，则代表全流程修复完毕！

如多次排查依然无法联网，说明所用机场落地线路可能存在大面积故障，可前往 [机场推荐列表](/recommend/) 选择客观测速达标的优质服务商。
